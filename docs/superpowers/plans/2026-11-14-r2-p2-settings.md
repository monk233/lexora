# R2 P2 设置窗口重写 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 React 重写 `settings` 窗口，使 72 个控件（C01–C72）、6 张卡片、自动保存状态机、5 条事件订阅与 44 条验收断言全部对等可用，并让 `frontend/dist` 取代 `web/` 成为设置页唯一实现。

**Architecture:** 窗口根组件 `SettingsWindow` 依次挂载 `I18nProvider`（locale 由后端 `state.app.locale` 驱动）与 `SettingsFormProvider`（草稿 + 500ms 防抖 + 串行保存队列 + 保存状态机）；六张卡片各自消费 `useSettingsForm()`，通过 `lib/settings/api.ts` 的**类型化薄包装**调用既有 `settingsAPI`（IPC 命令名一个不改）；纯逻辑（保存队列、快捷键解析、技能分类合并、格式化、更新状态机）抽成无 DOM 的模块并单测，组件用 Testing Library 断言可观察行为。DOM 结构完全重写，不照搬 `web/index.html`。

**Tech Stack:** React 18.3 + TypeScript 5 + Tailwind CSS 3.4 + shadcn/ui 源码（Radix 原语）+ lucide-react + Vitest 5 / @testing-library/react / jsdom。

**范围说明：** 本计划只覆盖 spec（[2026-11-14-r2-rare-ui-design.md](../specs/2026-11-14-r2-rare-ui-design.md)）§8 的 **P2 settings**。P3–P6（picker、quicktranslate、capture、收尾）不在本计划内。功能范围的唯一权威来源是 [p2-settings-inventory.md](../../../.superpowers/sdd/2026-11-14-r2-p0-p1-frontend-foundation/p2-settings-inventory.md)（下称"清单"）；`web/index.html`、`web/settings.js`、`web/settings.css` 是**行为规格**，不是要移植的 DOM。

**基线：** 分支 `feature/r2-rare-ui`。本计划起草于 HEAD `178f335`；起草期间并行任务 P2-1 已落地为 `bec1af6`（`feat(web): add remaining shadcn primitives and toast wiring`），补上了 `card/textarea/badge/progress/tabs/toggle-group/collapsible/scroll-area/separator/toaster/use-toast` 与对应 Radix 依赖。因此 **Task 1 只做语义对齐（4 条 / 3.6s / tone / Badge tone / Progress clamp），绝不重复实现**；每个任务开工前先 `git log --oneline -3` 与 `git status`，确认没有并行实现者正在改同一批文件。

## Global Constraints

- React / ReactDOM：`18.3.x`；TypeScript：`5.x`；Tailwind CSS：`3.4.x`（禁止 Tailwind 4）；Vite / Vitest 版本由现有 `package-lock.json` 锁定，不得升级。
- **禁止 Rare UI 根入口导入**：只允许 `@rare-ui/core/styles.css`、`/charts`、`/video`、`/datepicker`、`/carousel` 五个子路径；`npm run lint:imports` 必须 exit 0。P2 的功能清单里没有图表/轮播/日期/视频需求，因此**本计划不引入任何 Rare UI 组件**（基础组件一律来自 `frontend/src/components/ui/`）。
- **不再新增 npm 依赖**（不引入拖拽库、表单库、状态库）。P2-1 已补的 Radix 包视为既有资产；本计划其余需求一律用现有 `@radix-ui/*` + 本地受控组件实现（用到本地实现时任务里会说明理由）。若实现中发现必须新增依赖，**停止并上报 controller**，不得自行 `npm install`。
- **不改 Rust**：`src-tauri/**` 零改动；不改 `docs/contracts.md`；设置 schema 保持 `11`；版本号保持 `0.4.3`。
- **保留 `settingsAPI` 的全部 IPC 命令名与事件名**（一个都不改、不新增、不重命名）：`get_state`、`update_settings`、`reset_settings`、`test_online`、`list_online_models`、`download_engine`、`download_model`、`cancel_download`、`import_model`、`remove_model`、`start_local`、`restart_local`、`stop_local`、`open_dir`、`open_external`、`set_start_at_login`、`capture_set_hotkey`、`quick_set_hotkey`、`quick_history_clear`、`check_update`、`install_update`、`notify_update_available`、`quit_app`；事件 `state-changed`、`download-progress`、`update-progress`、`update-available`、`toast`。参数名保持 camelCase（`{patch}`、`{which}`、`{enabled}`、`{shortcut}`、`{baseUrl,apiKey,model,timeoutMs}`、`{id}`、`{file}`、`{url}`）。
- **自动保存语义必须逐条复刻清单 §4**：开关/select/分段控件立即保存；文本 500ms 防抖 + `blur` flush + `Enter` flush（多行用 `Ctrl/Cmd+Enter`）；`window blur` 与 `visibilitychange(hidden)` 全量 flush；`save()` 先 `deepMerge` 乐观更新再入队；队列**深合并、串行发送、绝不并发** `update_settings`；失败置 `error` + toast + `get_state` 回滚；成功且队列空才置 `saved`，2.2s 后回 `idle`。
- **`restart_local` 前必须先 `flushSaveQueue()`**，返回 `ok:false` 时中止重启并显示错误（清单 §4.12）。
- **快捷键录制必须用原生捕获阶段监听**：`window.addEventListener("keydown", handler, true)`，`preventDefault()` + `stopPropagation()`；禁止用 React `onKeyDown`、禁止用 Radix 组件拦截；`event.isComposing` 与 `event.repeat` 忽略；`Esc` 取消；`window blur` 取消；同一时刻只允许一个录制器。

## Radix Select 差异与映射（必须遵守）

原生 `<select>` 能用 `change` + `select.value = x` 直接改值；Radix `Select` 是 button + portal popover，**没有 `change` 事件、没有空字符串 item、不能在受控值不在选项内时静默显示**。四条 select（C05/C09/C45/C60）一律按下面规则实现：

1. **item 值不得为空串**。Radix 禁止 `<SelectItem value="">`，因此所有"空"语义用哨兵值，写回设置前翻译成真实值：
   - 模型名 `provider.online.model`：`__none__` → 写 `""`（"（未选择模型）"）；`__custom__` → 只切换 UI 到自定义输入态，**不写设置**。
   - 预设 `provider.online.preset`：`custom` 是真实预设 id（`web/shared/constants.js` 的第 8 项），不需要哨兵。
   - 默认目标语言 `picker.defaultTargetLang`：`auto` 是真实值，不需要哨兵。
   - 界面语言 `app.language`：`system` 是真实值，不需要哨兵。
2. **受控值是唯一真源**：`value` 来自 `useSettingsForm().settings`，提交走 `onValueChange(value)`；不允许 ref + 直接赋值 DOM（legacy 的 `setSelectValue` 语义由受控渲染承担）。
3. **已存值必须出现在选项里**：若 `provider.online.model` 已保存但不在拉取到的模型列表里，必须注入一个 label 为 `settings.onlineModel.current`（`{model}`）的真实 item，否则触发器只会显示 placeholder（legacy 用同名字符串拼接）。选中值不在集合时 `value={undefined}` + `SelectValue placeholder={t("settings.onlineModel.none")}`。
4. **测试方式不同**：组件测试必须先 `fireEvent.click(screen.getByRole("combobox"))` 打开下拉，再 `click(screen.getByRole("option", { name: ... }))`；不能 `fireEvent.change`。断言写回的 patch 而不是 DOM 的 `value`。
5. **语言切换重建选项**：选项标签用 `t()` 在渲染期计算（不缓存 `data-locale` 签名），语言变化自然重建；Radix 自带 typeahead 保留。
6. **高度与可访问性**：`SelectTrigger` 用默认 `h-9`（36px，符合契约 32–36px），并保留可见 label（`htmlFor` 指向 trigger 的 `id`）。

| 控件 | 设置路径 | 选项来源 | 特殊值处理 |
| --- | --- | --- | --- |
| C05 服务商预设 | `provider.online.preset` | `PRESETS` 8 项（`settings.preset.<id>.label`） | 选 `custom` 时清空 baseUrl/apiKey/model/modelsBaseUrl |
| C09 模型名 | `provider.online.model` | 拉取缓存 + 当前已存值 + `__none__` + `__custom__` | `__none__`→`""`；`__custom__`→显示 `C10` 输入框并聚焦 |
| C45 默认目标语言 | `picker.defaultTargetLang` | `LANGUAGES`（38）+ `auto`，label `settings.targetLang.<code>` | 39 项全部是真实值 |
| C60 界面语言 | `app.language` | `system` / `zh` / `en` | label：`common.followSystem` / `简体中文` / `English` |

```ts
export interface SaveQueueOptions {
  send: (patch: SettingsPatch) => Promise<SaveResult>;
  onStatus: (status: SaveStatus) => void;
  onSaved: (state: StatePayload) => void;
  onFailure: (error: string) => void;   // 调用方负责 toast + refreshState 回滚
  savedIdleMs?: number;                 // 默认 2200
}
export interface SaveQueue {
  enqueue(patch: SettingsPatch): void;
  flush(): Promise<{ ok: boolean; error?: string }>;
  pending(): boolean;
  dispose(): void;
}
export function createSaveQueue(options: SaveQueueOptions): SaveQueue;
```

语义（必须与 `web/settings.js:391-429` 等价）：`enqueue` 用 `deepMerge` 合并到 `queued` 后立即触发 flush；`flush` 在 `sending` 为真时返回当前 in-flight promise（**同一时刻只有一个 `update_settings`**）；发送前 `setSaveStatus("saving")`；成功 → `onSaved(state)`，若队列已空则 `saved` 并在 `savedIdleMs` 后 `idle`；失败 → `error` + `onFailure(error)`，**不阻塞后续队列**（finally 里解锁再 flush）；`flush()` 的 Promise 解析为最终 `{ok}`（失败时为 `{ok:false,error}`）；`dispose()` 清定时器。
